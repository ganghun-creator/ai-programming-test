# ai-programming-test
안녕하세요# Week 11 - 테스트 코드 작성 및 GitHub 문서화

## 1. 프로젝트 소개

Python의 pytest를 이용하여 CSV 파일을 읽는 load_scores 함수의 테스트 코드를 작성하였다. 또한 AI에게 코드와 명세를 각각 제공하여 테스트 코드를 생성하고 결과를 비교하였다.

## 2. 테스트 실행 방법

```bash
pip install pytest pytest-cov
pytest -v
pytest --cov=load_scores --cov-report=term-missing
```

## 3. AI 테스트 코드 비교

| 구분 | 테스트 개수 | 통과 | 실패 |
|---|---:|---:|---:|
| AI A (코드 제공) | 14 | 14 | 0 |
| AI B (명세 제공) | 11 | 11 | 0 |

AI A는 실제 코드를 제공하여 테스트를 생성하였고, AI B는 코드 없이 명세만 제공하여 테스트를 생성하였다.

두 테스트 모두 정상적으로 통과하였으며, A는 경계값을 더 다양하게 확인하였고 B는 빈 줄에 대한 테스트를 포함하였다.

## 4. 코드 커버리지

실행 명령어: `pytest --cov=load_scores --cov-report=term-missing`

| 항목 | 결과 |
|---|---:|
| 전체 구문 수 | 45 |
| 실행되지 않은 구문 | 9 |
| 코드 커버리지 | 80% |
| 미실행 코드 줄 | 77~86 |

코드 커버리지는 80%로 확인되었다. 77~86번 줄은 테스트 과정에서 실행되지 않은 부분이므로 해당 부분을 확인하고 추가 테스트가 필요한지 검토할 필요가 있다.

## 5. 버그 발견 실험

`bug3_logic.py`의 find_max 함수에 대한 테스트를 작성하였다.

전체 8개 테스트 중 5개는 통과하였고 3개는 실패하였다.

실패한 테스트는 모두 리스트의 마지막 원소가 최댓값인 경우였다.

원인은 반복문의 범위를 설정할 때 마지막 원소를 확인하지 않도록 작성했기 때문이다.

이를 통해 테스트 코드를 이용하면 프로그램에 존재하는 논리적 오류를 발견할 수 있다는 것을 확인하였다.

## 6. 실험 결과 및 느낀 점

이번 실습을 통해 AI에게 코드를 제공하는 방식과 명세를 제공하는 방식에 따라 생성되는 테스트 코드가 달라질 수 있다는 것을 확인하였다. 또한 코드 커버리지를 통해 테스트되지 않은 부분을 확인할 수 있었으며, 버그가 있는 코드도 테스트를 통해 오류를 찾아낼 수 있다는 것을 알게 되었다.
